# P20a gate R1: `etendue real calibrate` equals calibration-rs's own run

**Gate R1:** on `kuka_1` and `DS8`, the report's estimates and residuals equal calibration-rs's
own run of the same manifest. Both call calibration-rs's dataset runner, so any difference is
etendue's.

**Verdict: PASS.** On both datasets every compared number is bit-identical (max |Δ| = 0).

## When and where

- Measured 2026-11-13, Apple M4 Pro, rustc 1.95.0, release builds.
- etendue commit `57be13c`, branch `p20a/real-calibrate`.
- calibration-rs `v0.18.0`, a clean clone of the tag; its `vcal` built from it
  (`cargo build --release -p vision-calibration-cli`).

## Method

`tests/r1.rs`, run with
`VCAL=<calibration-rs>/target/release/vcal cargo test --release -p etendue-cli --test r1 -- --ignored --nocapture`.

For each dataset it runs `vcal run <manifest> --redetect` and `etendue real calibrate`'s library
call, each detecting afresh into its own cache, and compares bit for bit:
- etendue's kept export (`result.json`) with vcal's `calibration.json`: every number;
- the report's estimate (each camera's intrinsics, Brown-Conrady distortion and `cam_se3_rig`,
  and the hand-eye) with vcal's export read through calibration-rs's own types;
- every residual (observed and projected pixel, error) in calibration-rs's order, and the mean;
- σ (the covariance's diagonal) and its labels;
- the quality report (`quality.json`), every field;
- the views used, against vcal's count.

## Data

- `kuka_1`: calibration-rs's `data/kuka_1` at the tag, images from its LFS. Single-camera
  hand-eye, a 17 × 28 chessboard, 30 poses.
- `DS8`: calibration-rs's `data/DS8` manifest at the tag, with the images downloaded separately.
  The local copy of the images is PNG (converted from the published TIFF and JPEG), so the three
  image globs read `*.png`; everything else in the manifest is unchanged. Both runs read
  the same adapted manifest, so R1 compares like with like. Three-camera rig hand-eye, a 10 × 14
  chessboard, 42 poses.

## Results

| Dataset | Views used | Points | Mean reprojection (px) | RMS per axis (px) | Max (px) | Implied noise σ (px) | Verdict | Numbers compared | Differ | max \|Δ\| |
|---|---|---|---|---|---|---|---|---|---|---|
| `kuka_1` | 30 / 30 | 14 280 | 0.1347 | 0.1077 | 0.4951 | 0.1080 | pass | 230 297 | 0 | 0 |
| `DS8` | 33 / 42 | 13 440 | 0.2565 | 0.2216 | 1.5415 | 0.1847 | warn | 218 272 | 0 | 0 |

`DS8`'s runner left out 30 detections in 9 views (too few features: the manifest keeps only
complete boards). Its `warn` is calibration-rs's: the projection σ at the image corners and a few
outlier views (view 16 on cameras 0 and 1), as `vcal` reports it too.

## Found and fixed

Before this step a report's per-feature error was recomputed by etendue as `hypot(du, dv)`.
calibration-rs's own `error_px` is the vector norm `√(du² + dv²)`, and the two differ in the last
bit for about one residual in six (2298 of 14 280 on `kuka_1`). The report now carries
calibration-rs's value, for synthetic runs too.

## CI

R1 is local only. `DS8`'s images are not in git; `kuka_1`'s are in calibration-rs's LFS (85 MB),
and running R1 in CI would also need calibration-rs's CLI built from the tag and etendue in
release, more than one job's worth. CI covers the parts without data: dataset resolution, the
real run kept and read back (version 2), and the report schemas.
